Web Art, teaching visual design inside a real design system

The Problem

Design gets left out of the push to teach kids tech

Young people are increasingly taught to code and engineer. The fundamentals that make something clear and usable, like typography, color theory, grid systems, spacing, hierarchy, whitespace, contrast, and accessibility, get far less attention.

Core idea

Teach visual design by having students work inside a real design system, instead of learning principles in isolation.

The Product

Three studios in one app

Web Art runs in the browser as a single app with three studios, each focused on a different part of design.

Web Design Studio. Students build multi-page websites on a 12-column grid with drag-and-drop and an 8pt spacing system. Navigation stays matched to page names, and the Inspector gives live, WCAG-based feedback as they design.

Component Lab. Five interactive workspaces for buttons, badges, pop-ups, cards, and form fields, each with style pickers and advanced controls.

Bug Sandbox. A motion scripting environment.

Key Decisions

The choices that shaped it

Real structure from the start. The 12-column grid and 8pt spacing system are the same kind of structure professional design teams work within. Students learn layout by making decisions inside that structure.

Feedback while students work. Accessibility guidance appears live in the Inspector as students design, rather than as a separate lesson.

Local-only data. Student work is saved only in the browser. That keeps the project out of scope for most student data privacy obligations, like COPPA and FERPA, and keeps the pilot low cost with a short setup time.

The tradeoff. Shared lab computers make browser-only storage fragile, so student work can be lost. I treat that as the main practical risk for the pilot, which is why an export feature has to come before any wider rollout.

How I Build It

My judgment, AI for speed

I lead Web Art as creative director and decision-maker. I use Claude as a thinking partner and collaborator for both building the product and articulating it, not mainly as a code generator. AI gives me speed and room to iterate. The direction and point of view are mine.

Build sessions are iterative with tight scope control: each round changes only what I asked for, and anything outside that gets rolled back.

Technically, it is a single React application of about 4,800 lines, packaged with Vite and Tailwind, with a README that maps the codebase's landmarks. I have since moved development into VS Code with Claude Code.

What's Next

Making it safe for shared school computers

The curriculum is being piloted with students now. The most important next build is export and download, so students keep their work even when a shared lab computer loses it.
