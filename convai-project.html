The problem

A static screen left users guessing.

How can motion show when the assistant is ready, working, and done?

A blank prompt box gave first-time users no sign the assistant was ready, and most first sessions ended without a prompt sent. Once they did send one, the screen gave little feedback, so they couldn't tell if the agent was thinking, stuck, or done.

The experience

Motion that shows what the AI is doing

01

A chatbox that invites a first prompt

Example prompts type themselves into the chatbox, and a traced ring shows the assistant is listening. The ring speeds up while the agent works.

02

Motion with a spec behind it

I set the timing for every landing page element so design and engineering built the same thing. The illustration drifts slowly and never competes with the input.

03

A spec the whole team worked from

The motion page held the problem, goals, success metrics like frame rate and reduced-motion coverage, scope by epic, and the full motion spec.

Decisions and tradeoffs

What I chose, and what I gave up

01

Reuse the listening ring instead of adding a spinner

A separate loading spinner was the obvious option. Speeding up the ring users already knew kept one signal for the assistant's state and one less element to build.

02

Motion follows state, not a timer

Fixed timings were simpler to build, but they told users the agent was done before it was. Tying motion to the real response state took more engineering work.

03

User input always interrupts motion

Letting animations finish looked smoother, but typing while a chip animated could overwrite what the user wrote. Their input wins.

04

Reduced motion ships with beta

Treating it as a follow-up would have saved time before launch. I made it a beta requirement instead, since it affects who can use the product at all.

I also built on the motion system I already owned rather than inventing new patterns, which kept the app builder consistent with the rest of Oracle's products.

Self-starter

Keeping Jira alive when the team let it go

Midway through, the Gen AI team stopped detailed Jira tracking. I kept it going on my own, because a shared record of what was in progress, blocked, and done was the easiest way for design, engineering, and QA to stay on the same page.

Each week I updated the board, posted a status page, and reviewed session replays to see how the motion behaved in real conversations, filing each problem to Jira with a link back to its source.
