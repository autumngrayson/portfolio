Confidentiality note Oracle's product work is confidential, so this case study describes the problem, my role, and the results without internal screens or product details.

The Product

The product

In the app builder, a person types a request in plain language and the system generates a working application. The conversation sits on one side of the screen, and a live preview of the app builds on the other. My team was responsible for the motion, meaning what the interface shows while the system is working.

The Design Problem

The design problem

Generating an app takes time, and most of the work happens where the user can't see it. In a typical interface, clicking something gets an immediate response. Here, the interface had to show that the system was still working, so a pause wouldn't look like the product was stuck.

Core question

What should someone see while the AI builds their app, so that waiting feels like progress?

How I Ran It

How I ran the team

I ran the four-person team in agile sprints against a four-month deadline, which ended with an MVP review with leadership.

We built on the motion design system I already owned instead of creating new patterns for this product. That kept the app builder consistent with the rest of Oracle's products.
